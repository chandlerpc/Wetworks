# Wetworks handbook (knowledge lines)

Everything about how Wetworks was built and why, distilled from the build sessions (Nov 2026). Every "- " line is
loaded into memory on start; the section heading sets the kind. The full narrative is docs/handbook.md, which agents
can read with the read_handbook tool. No secrets belong in this file.

## decision
- Wetworks' autonomy policy (Patrick's choice): agents act freely inside Wetworks; anything that leaves Wetworks or can't be undone (messaging other people, posting, merging code, spending money, switching every agent's model) needs Patrick's approval in the console's Needs you panel.
- Wetworks never sends anything to other people as Patrick: no emails, no outreach, no social posts. Agents draft; Patrick reviews, copies and sends or posts himself.
- Merging any pull request into main always needs Patrick's approval. The Code cell never pushes to main and is blocked from editing .git/, .github/ workflows, .env files (except .env.example), keys and certificates.
- After a merge the MSI does not update itself; Patrick runs git pull and docker compose up -d --build. This is deliberate so Wetworks can't restart itself with broken code.
- When console or code files change, the MSI needs docker compose up -d --build (a plain restart does not pick up new code because the image must be rebuilt).
- Spending: $20 was the AI spending limit for the build week of Nov 3, 2026. Free models by default; small paid tests are fine; no real spend until everything is proven. Patrick plans to upgrade to Claude Max on Friday Nov 6, 2026 and set up plans for other AI then.
- Claude Fable and GPT-6 Astra are approval-only models because they are expensive.
- Design principle: get the most out of every token, not maximum token spend. Use the cheapest model that can do the job and escalate only when needed.
- Discord is not the main control surface. Patrick commands Wetworks through the ops console (desktop or phone), by talking to C.L.a.i.R (typed or voice), or from his phone. Discord gets briefs and urgent notices only.
- The ops console UI direction: a dark, gritty pixel-art ops center in a top-down 3/4 view (Streets of Rogue style), with rooms from the licensed Retro Cybercity Corporate tileset and characters to be made with an image AI. An earlier isometric canvas version was replaced because hand-drawn canvas shapes couldn't reach the look Patrick wanted.
- The Retro Cybercity Corporate tileset is licensed to Patrick: it may not be redistributed or used to train AI image generators, so it is never committed to git and never uploaded to an image AI; style is described in words instead.
- Finance data never leaves the MSI: only the local model reads transactions; the brief gets totals at most; cloud agents get nothing unless finance share_with_cloud is set true in config/finance.toml; drills only see fake numbers.
- Day Job (Novarad support) material stays on the MSI: patient details are scrubbed before anything is stored or shown to a model, only the local model reads tickets, cloud agents can't search it, and the brief gets counts only.
- The Observer may watch sensitive screens (money, passwords, Novarad and patient screens) so it learns those workflows, but it must never save sensitive details: no window titles for those screens, task-level descriptions only, with amounts, numbers, names, emails and patient identifiers stripped. Screenshots are never written to disk.
- Patrick has employer approval to run The Observer on his work PC but is not setting it up there yet.
- The Observer's suggestions (brief times, a morning prep, automation ideas) arrive as approval cards; nothing changes without Patrick's OK, and each idea is only suggested once.
- The Architect alone was switched to Claude Opus 5.5 on Nov 4, 2026 to test his capability (WETWORKS_ARCHITECT_BRAIN=claude-api); cells, Splinters and C.L.a.i.R stay on free brains. Monthly budget raised to $20 for the test.
- While The Architect thinks on a cloud model (Claude), private rooms stay closed to him: finance unless share_with_cloud is true, Day Job and The Observer never.
- Mission priorities, in order: make money, make the day job easier, manage finances, free up time, build games, create content.
- Rooms were unsealed in this order: Finance, Day Job, Content. Game Dev stays sealed until Claude is fully connected (Friday), because design docs and prototype code need a stronger model than the local one.
- C.L.a.i.R stays hosted on her Cloudflare Worker (in the chandlerpc/portfolio repo) and can be rebuilt there as needed; her private Wetworks mode is a self-contained block so it never disturbs her public recruiter mode.
- C.L.a.i.R speaks with Azure's en-IE-EmilyNeural voice (young Irish female) on hold-to-talk plus hands-free mode with a wake phrase, stop phrases and an idle timeout, on iPhone and Android.
- New cells get a 2-week trial before being made permanent.
- Patrick's past Claude chats can't be imported yet: the data export is emailed to an account address he lost access to. When he moves to his new Claude account he can export there and load it with the import-chats command.

## preference
- Patrick wants terminal commands given one per code block, never chained into one block.
- Patrick prefers precision over breadth and fixes at the root cause, not workarounds that paper over a problem.
- Patrick likes to see results visually (screenshots of UI changes) and gives direct feedback; when he says he likes something as it is, keep it and fix only what he asked.
- When Patrick asks for a UI fix (for example scrolling), change only that behaviour; he objected once when a layout was redesigned instead of just fixing the scroll.
- Patrick wants the newest activity at the top of activity lists.
- Patrick likes cross-vendor review of agent work and wants as many models as possible available (Claude, Gemini, Grok, local models), each used where it fits best.
- Patrick wants all agents constantly learning; the endgame is his own AI model hosting platform to develop, train, deploy and use custom LLMs 24/7 (The Forge is the start of it).
- Patrick wants The Architect to be decisive but economical, and to bring him finished recommendations with a clear plan and what he needs from Patrick.
- Patrick's content voice: plain, practical and specific, first person, short sentences, concrete numbers over hype, no buzzwords, at most two hashtags on LinkedIn, end with a real question or takeaway.

## fact
- Wetworks runs 24/7 on an MSI Raider GE78HX laptop: RTX 4070 Laptop GPU with 8GB VRAM, 32GB RAM, Windows 11, WSL2 Ubuntu 24.04 with systemd, Docker Engine inside WSL (not Docker Desktop), NVIDIA GPU passthrough. Windows user folder is pchan; the Linux user is savage; the repo lives at ~/Wetworks.
- Patrick develops on his Mac; the MSI pulls from GitHub and runs. The repo is github.com/chandlerpc/Wetworks (private). C.L.a.i.R's Worker is clair-worker.js in github.com/chandlerpc/portfolio, served at clair.pchandlerc.workers.dev with a private /wetworks route.
- The MSI uses WSL mirrored networking; the console is reached over Tailscale with tailscale serve providing an https ts.net address, plus a bearer access code (WETWORKS_CONSOLE_TOKEN). The API refuses everything when no access code is configured.
- Patrick rarely plays Black Desert Online on the MSI, and only AFK with the game minimized, so the GPU is effectively dedicated to Wetworks.
- Wetworks' Docker Compose services: architect (Python app, API and console on port 8700, scheduler), ollama (local models on the GPU, model kept loaded), searxng (self-hosted search), whisper (faster-whisper medium.en on CPU for speech), whisper-fast (base.en on CPU for wake-phrase checks), sandbox (code test runner: internal-only network, read-only, no secrets), forge (Unsloth fine-tuning on the GPU, runner on port 8900).
- The local model is gemma4:12b in Ollama (about 7.5GB of the 8GB VRAM), with thinking switched off so it answers directly.
- Claude tiers in Wetworks: route = claude-haiku-5-5, work = claude-sonnet-5-5, think = claude-opus-5-5. Ledger prices per million tokens: Opus $4 in / $20 out, Sonnet $2 / $10, Haiku $0.10 / $0.50.
- Every paid model call is recorded in a SQLite ledger with tokens and cost. At 80% of the monthly budget the brief warns; at 100% non-essential calls are refused and essential ones drop to the cheapest tier.
- Brains: agent_brain (local or claude-api) drives cells and Splinter research; architect_brain overrides it for The Architect only; code_brain drives the Code cell (local, claude-api, and claude-code planned for Friday on the Max plan); C.L.a.i.R thinks on Gemini 3.8 Flash (since Nov 4, 2026) through her Worker's step mode with the local model as backup.
- Settings live in .env with the WETWORKS_ prefix (plus ANTHROPIC_API_KEY, XAI_API_KEY, AZURE_SPEECH_KEY, AZURE_SPEECH_REGION, GITHUB_TOKEN without it). Settings changed from the console (for example an approved Observer brief time) are saved in data/overrides.json and applied on restart.
- Briefs go to Discord at 07:00 and 21:00 Eastern by default, with host health, spend, findings grouped by topic, and summaries from each room at their allowed privacy level.
- The Architect (commander) checks in twice a day, at 07:30 and 21:30 (Patrick's choice, Nov 4, 2026), on Claude Sonnet. Each check-in he reviews findings, leads, missions, follow-ups and memory against the priorities, opens at most 2 missions (3 open at once, 6 per day), leaves follow-ups, and reports to the activity feed; Discord only for things needing action today.
- Between check-ins The Architect only checks in early for something major: a failed mission, a finished code mission, an act-today finding (importance 5), a top-fit lead, or a note from C.L.a.i.R. At most 3 extra check-ins a day; routine mission results wait for the next check-in.
- When Patrick chats with The Architect he thinks on Claude Opus; his scheduled check-ins use Sonnet to save money.
- On Claude, The Architect gets 14 steps per command cycle, 10 per chat reply and 3,500 tokens per step, and doesn't pause while The Forge trains. On the local model he gets 8 steps per cycle and 5 per chat reply.
- The agent runtime is a JSON step loop: each step the model returns {"thought","tool","args"} to call a tool or {"thought","done"} to finish; tool results come back as observations; there are step limits, bad-step recovery, and tool failures become observations rather than crashes. Gated tools create approval requests instead of running.
- The Architect's tools for work: search_web, read_page, recall, remember, search_past_chats, read_past_chat, list_missions, get_mission, start_mission (research or code), recent_findings, list_leads, research_lead, note_lead, draft_outreach, follow_up_later, tell_patrick (Discord), content_ideas, add_content_idea and read_handbook.
- The Architect's Forge tools: forge_status, build_training_data, queue_training, benchmark_model, and the approval-gated switch_local_model. His other gated tool is merge_pull_request. finance_summary, dayjob_search and observer_today only return detail when he thinks on the local model.
- C.L.a.i.R's tools are like The Architect's but she uses tell_architect to hand him strategy or multi-mission work, she has no tell_patrick (she is already talking to him), and she never sees private room details because she thinks on Gemini.
- Missions are run one at a time by the Splinter Operator (so the GPU isn't split): plan, research with SearXNG and page reading, then a write-up with numbered citations and a Next step line. Sources always come from real search results. Missions that crash go back to the queue on restart.
- Research tools track every URL an agent has seen; findings and leads can only point at those URLs, so links are always real. Page reading only reaches public internet addresses and checks every redirect.
- The Code cell (code missions): fresh branch wetworks/mission-<id> from main, the brain picks files and proposes full-file edits, edits run their tests in the sandbox, one repair round, commit staged files only, push the branch, open a pull request (draft if tests fail). Git hooks and fsmonitor are disabled and the GitHub token is passed per command, never written to the clone.
- Intel (Sleeper) runs 20 minutes before each brief over the topics in config/intel.toml (AI models & tools, money opportunities, job market, Black Desert Online, and more can be added). On the local stack SearXNG searches and the local model picks and summarises real results; it falls back to a fixed routine if the model doesn't search. Findings' URLs are de-duplicated for 14 days.
- Revenue (Sleeper) hunts once a day 45 minutes before the morning brief, rotating search terms in config/revenue.toml, scoring local independent businesses 1 to 5 for fit with CodeVoyage's services (AI chatbot, workflow automation, analytics dashboard), and drafting outreach for fit 4+. Job-board pages are evidence only and never identify a business.
- Lead follow-ups: strong new leads get a Splinter research mission first and the first email draft waits for it. When Patrick marks a lead Contacted, follow-ups are due after 4 days and then 7 days (config followup_days); the brief reminds him and a follow-up draft is waiting; replies or closing a lead stop the nudges.
- Memory: SQLite full-text search, no model needed. config/profile.md is pinned for every agent; config/knowledge/*.md lines load on start; agents recall related memories for each message and can remember durable facts Patrick states. The Learner (The Archivist) runs at 23:30 to extract durable facts from the day and archive mission details older than a year with a heads-up the week before.
- Every agent decision is recorded in traces.db with the brain that made it. Gemini and Claude decisions are teacher lessons; a lesson only counts if it finishes or calls a tool that was actually offered.
- The Forge: Unsloth QLoRA fine-tuning of unsloth/Qwen3-4B-Instruct-2507 on the RTX 4070, jobs in the 01:00 to 05:00 window unless started now. Before training it unloads Ollama and pauses local thinking; after, it reloads. Output is a q4_k_m GGUF registered in Ollama as wetworks-<name>:<id>. The agent-steps dataset needs at least 150 teacher lessons (10% held out); benchmarks score valid step, same action and same tool.
- Forge drills bank lessons faster: every 15 minutes from 07:00 to 23:00, C.L.a.i.R or The Architect works a practice request on Gemini with the real tool list. Read-only tools run for real; anything that changes state is simulated; private rooms return fake samples. Drills stop at 120 Gemini calls a day, on a Gemini 429 (until the next day), and at 600 lessons.
- Gemini 2.5 Flash's free tier is shared between C.L.a.i.R's chats, drills and the public recruiter on Patrick's portfolio site.
- Voice: Whisper medium.en hears requests; whisper-fast base.en only listens for the wake phrase; transcripts drop Whisper's silence hallucinations and fix house words (Wetworks, The Architect, The Forge, NovaPACS); Whisper's hint includes lead names and WETWORKS_VOICE_VOCAB. Replies are voiced in two parts so the first sentence plays sooner. Azure TTS free tier is 500k characters a month and Wetworks stops speech at 480k.
- The kill switch (Floor, or POST /api/halt with confirm HALT) is saved in data/HALTED and survives restarts. While set, cells, command cycles, missions, drills and Forge jobs don't start new work; chat still works.
- The Floor is a top-down 3/4 pixel-art map of the ops center: Intel Watch, Revenue Room, Splinter Ready Room (top row); Archives, Command Deck, Comms Booth, Code Bay (middle); The Forge, Day Job, Finance, Game Dev (sealed), Content (bottom). Agents walk between home, station and bunk; lamps brighten when busy and pulse red when blocked; the red phone on the Command Deck rings for approvals; the Forge glows with GPU load. A Look panel sets colour grade, darkness and glow per device.
- The art pack is installed on the MSI with python3 -m wetworks.tools.install_art <path to the .7z>, which extracts the five native interior sheets into wetworks/console/art/ (git-ignored). The image-AI art spec for characters and missing ops props is docs/art-spec.md; custom sprites go in wetworks/console/art/custom/.
- Finance (The Bookkeeper): bank or card CSV import in the console (account numbers masked, duplicates skipped, card exports' signs flipped, undo per import); categories from config/finance.toml rules, Patrick's corrections (remembered per merchant) and the local model; recurring charges and bills due; budgets per category. Runs 20 minutes before the morning brief.
- Day Job (The Technician): a library of Patrick's notes, KB files (text, Markdown, HTML, CSV, email, PDF) and fixes with full-text search; pasted tickets are scrubbed of patient details, then the local model drafts likely cause, steps, questions and a reply from his own fixes first; solving a ticket saves the fix. It never connects to Novarad systems.
- The Observer: helpers on Patrick's machines (observer/agent.py for Mac and the MSI via WSL and PowerShell; observer/agent.ps1 for Windows with nothing installed) report app, window title and idle time, plus a screenshot about once a minute that the local vision model describes in one sentence and discards. It builds day views, habits, a nightly digest at 23:15, and teach-a-task playbooks.
- Content (The Writer): suggests post ideas grounded in the week's missions, Intel and Observer digests, drafts them for LinkedIn, X, blog and portfolio in Patrick's voice on the local model, keeps a posting calendar, and flags drafts that mention never_mention words. Runs 30 minutes before the morning brief.
- The test suite runs with pytest (169 tests at the Content and Architect-on-Claude milestone); tests cover privacy rules, approvals, the kill switch, rooms, voice, drills and the agent runtime.
- Spend at the start of the build week was $0.43, mostly testing.

## project
- Wetworks is Patrick's 24/7 multi-agent ops center (repo chandlerpc/Wetworks): The Architect oversees; C.L.a.i.R handles comms; Splinters are on-demand strike teams for one mission; Sleepers are background agents that wake on schedules or triggers; The Forge is the local model lab.
- Wetworks' rooms and their agents: Command Deck (The Architect), Comms Booth (C.L.a.i.R), Intel Watch (Intel), Revenue Room (Revenue), Splinter Ready Room and Code Bay (Splinters), Archives (The Archivist and The Observer), The Forge (Forge Operator), Finance (The Bookkeeper), Day Job (The Technician), Content (The Writer), Game Dev (sealed).

- Known gaps: The Architect has no tool to look up pull requests (a drill showed he asks Patrick for the number); approved brief-time changes only apply after a restart; Observer screenshot descriptions depend on the local model reading images.
- The model router (Nov 4, 2026): every paid, non-private model call goes through wetworks/models.py using config/models.toml. Roles: plan (Opus 5.5, GPT-5.5, Gemini 4 Argon), reason (Sonnet 5.5, Gemini 3.8 Flash, GPT-5.4 mini), code (Sonnet, GPT-5.5), review (GPT-5.5, Sonnet, Gemini 3.1 Pro), write (Gemini 3.8 Flash, Sonnet), long (Gemini 3.1 Pro, Argon), bulk (Gemini Flash, Haiku, GPT mini), live (Grok 4.7). It uses the first model with a key and budget left, falls back down the list, then to the local model.
- Monthly AI budget is $100 since Nov 4, 2026, with Anthropic first: caps of Anthropic $55, xAI $15, OpenAI $15, Google $15. Patrick wants many models used, each where it fits, without going wild on cost.
- Cross-vendor review: outreach drafts and unflagged content drafts get an automatic second opinion from a different AI company's model, shown under the draft. Agents have a second_opinion tool for important plans and drafts; a review never comes from the author's company or the local model.
- Intel topics marked live = true in config/intel.toml (AI models & tools, Money opportunities) use Grok's live web and X search; others use the usual route. Grok Bot is not used: it has no inbound API, and Wetworks does the same work itself.
